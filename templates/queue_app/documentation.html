1. Introducción

Objetivo del sistema

NexHUs centraliza el escaneo de HUs, la agrupación por pallet y el procesamiento secuencial en SAP (Order Acknowledge y Separazione) hasta generar e imprimir el documento de recepción de material para el área de Inbound.

Problema que resuelve

Reduce trabajo manual, evita saltos de impresión, mantiene trazabilidad y sincroniza la UI con el backend mientras SAP, Celery y WebSockets trabajan.

Beneficios

Operación más rápida, menos errores de captura, visibilidad en tiempo real, ahorro de hojas/tóner gracias al diseño optimizado del recibo, y mejor soporte cuando hay fallas de SAP, Redis, Celery, base de datos o impresión.

2. Arquitectura General

Frontend Django Redis Celery SAP GUI PDF/Impresora

El frontend renderiza la cola y escucha eventos por WebSocket. Django recibe escaneos, valida datos, persiste HUs/pallets y despacha tareas. Redis funciona como broker, storage de locks y canal de coordinación. Celery ejecuta SAP GUI Scripting en modo secuencial sobre SAP Logon. Daphne sirve HTTP y WebSockets mediante ASGI.

  • Frontend: HTML, CSS y JavaScript para escaneo, tabla, progreso, diagnóstico y resincronización.
  • Backend: vistas Django, modelos, utilidades de cola y endpoints internos.
  • Base de datos: SQLite actual
  • Redis: broker Celery, locks, heartbeat y estado runtime.
  • Celery: worker único recomendado para evitar sesiones SAP concurrentes.
  • Daphne/Channels: servidor ASGI y WebSockets de actualización en tiempo real.
  • SAP GUI Scripting: automatiza Order Acknowledge, Separazione y generación de receipt dentro de SAP Logon.
  • SumatraPDF: imprime el documento de recepción con un diseño optimizado para ahorrar hojas, tóner y tiempo.

3. Flujo Operativo

  1. Escaneo de HU: el operador escanea o pega HUs en el input principal.
  2. Validaciones: se detecta origen, duplicados, longitud y separadores de pallet.
  3. Creación de pallets: ITA, FHR y BRA/ATL operan como single-HU; THA y CNA pueden agruparse.
  4. Envío a cola: el botón Iniciar Proceso despacha la tarea a Celery si hay worker activo.
  5. Procesamiento SAP: el worker ejecuta Order Acknowledge (F1) y Separazione (F2) de forma secuencial en SAP Logon vía SAP GUI Scripting.
  6. Receipt: después de F2 se usa ZE16 para generar el documento de recepción de material.
  7. Impresión PDF: pdf_receipt.py crea el PDF con el diseño optimizado y lo manda a SumatraPDF/impresora del área de Inbound.

5. Instalación

Requisitos

  • Windows con usuario interactivo abierto.
  • Python, SAP Logon (GUI Scripting habilitado), Redis para Windows y SumatraPDF.
  • Acceso de red al servidor y puerto definido para Daphne.

Crear entorno virtual e instalar dependencias

python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt

6. Configuración

La configuración principal vive en config/settings.py y variables de entorno. En producción deben revisarse DEBUG, SECRET_KEY, ALLOWED_HOSTS, Redis, usuario SAP e impresora.

  • .env: define secretos, usuario SAP, Redis, host LAN y rutas locales del servidor.
  • Base de datos: SQLite usa db.sqlite3; para SQL Server se deben traducir estas migraciones al motor definitivo.
  • Migraciones: los archivos en queue_app/migrations/ describen cómo crear o cambiar tablas Django.

Redis

Define broker, result backend, locks y señales runtime.

SAP

Usa credenciales configuradas por variable de entorno para abrir la sesión en SAP Logon. No exponer passwords en UI o logs.

Impresoras

Configurar SumatraPDF, impresora predeterminada del área de Inbound y permisos del usuario Windows.

8. Procesos de Negocio

Order Acknowledge

Primer paso SAP ejecutado en ZMOVEINBHU para reconocer el HU.

Separazione

Segundo paso SAP ejecutado en ZMMTIJSEP para completar separación.

Receipts

Documento final generado desde ZE16 e impreso con diseño optimizado vía SumatraPDF.

HUs

Handling Units escaneadas y guardadas como HUItem.

Pallets

Agrupación operativa de HUs con reglas por origen.

9. Integración SAP

SAP GUI Scripting controla una sesión de SAP Logon abierta en Windows. El worker Celery debe correr en una sesión interactiva y con --pool=solo --concurrency=1 para evitar conflictos entre tareas que compartan la misma sesión SAP.

TransacciónUsoEstado
ZMOVEINBHUOrder Acknowledge (F1) por HU.Activa
ZMMTIJSEPSeparazione (F2) por HU.Activa
ZE16Generación del documento de recepción / receipt para impresión.Activa

10. Diseño Optimizado de Impresión

El documento de recepción de material que ve el área de Inbound se imprime mediante pdf_receipt.py y SumatraPDF con un diseño pensado para reducir el consumo de hojas, tóner y tiempo de impresión frente a un formato sin optimizar.

Ahorro de hojas

El layout aprovecha mejor el espacio de la página para incluir más información por hoja, reduciendo el número de páginas impresas por recibo.

Ahorro de tóner

Se evitan rellenos sólidos, fondos oscuros y elementos gráficos pesados, priorizando texto y líneas finas.

Ahorro de tiempo

SumatraPDF se invoca en modo silencioso directamente desde Celery, evitando pasos manuales o diálogos de impresión por cada HU/pallet.

14. Manejo de Errores

  • HTTP 500: debe mostrarse en toast/diagnóstico y no perder el escaneo cuando sea recuperable.
  • Redis desconectado: bloquea dispatch de Celery y actualiza diagnóstico.
  • Celery detenido: no se debe iniciar proceso; el diagnóstico debe marcarlo como error.
  • SAP no disponible: usar estado cacheado/timeout y evitar congelar Daphne.
  • Impresora sin conexión: registrar error PDF/impresión y dejar HU/pallet trazable.

15. Diagnóstico del Sistema

El panel de diagnóstico permite ver estado de Django/Daphne, Redis, Celery, SAP, WebSocket, cola, base de datos y servicios locales. Sirve para soporte cuando la UI parece esperando o cuando un backend externo dejó de responder.

Django/Daphne

Confirma que el backend HTTP responde.

Redis

Confirma broker y locks runtime.

Celery

Confirma workers activos antes de procesar.

SAP

Confirma sesión SAP Logon disponible o estado no confirmado.

WebSocket

Confirma canal de eventos en tiempo real.

Base de datos

Confirma lectura/escritura y reporta errores readonly.

16. Seguridad

  • Activar autenticación y permisos por rol antes de exponer el sistema fuera del entorno controlado.
  • No mostrar passwords SAP, SECRET_KEY, tokens o rutas sensibles cuando DEBUG=False.
  • Usar ALLOWED_HOSTS exactos para el servidor LAN.
  • Revisar CSRF en endpoints críticos si se habilitan usuarios autenticados.
  • Con HTTPS, activar cookies seguras y HSTS según política de IT.

17. Mantenimiento

  • Respaldos: copiar base SQLite actual o plan SQL Server antes de cambios.
  • Logs: revisar logs de Django, Celery, diagnóstico y SAP al investigar fallas.
  • Actualizaciones: probar cambios con cola de ejemplo antes de producción.
  • Limpieza: definir política de histórico para HUs procesados y errores.
